Perintah `supabase db push` menerapkan migration lokal yang belum diterapkan; data legacy memerlukan proses import tersendiri. [Panduan migration Supabase](https://supabase.com/docs/guides/deployment/database-migrations)

File `ResourceCollection` dan `DocumentCenter` berisi **JavaScript Google Apps Script**, bukan SQL. File tersebut tidak dapat ditempel ke SQL Editor untuk membuat database. File di `docs/` merupakan laporan/bukti audit, bukan file database yang perlu diunggah.

## 1. Buka project yang benar dan periksa database

1. Buka [dashboard project DEV](https://supabase.com/dashboard/project/vvojshgcduqlugngpzkj).
2. Buka **Table Editor** dan pilih schema **public**. Saat ini daftar tabel memang kosong.
3. Buka **SQL Editor**, buat query baru, lalu jalankan pemeriksaan berikut:

```sql
select table_schema, table_name
from information_schema.tables
where table_schema = 'public'
  and table_type = 'BASE TABLE'
order by table_name;
```

Query tersebut hanya membaca daftar tabel. Hasil kosong berarti belum ada tabel public yang terlihat oleh sesi tersebut, bukan berarti koneksi gagal. Tabel akan muncul setelah migration pembuat tabel berhasil diterapkan ke project yang sama.

Jika daftar di extension VS Code berbeda dari dashboard, cocokkan project reference dan schema yang dipilih, lalu muat ulang daftar tabel. Pengaturan koneksi extension tersendiri belum diverifikasi dalam audit ini; koneksi MCP agent sudah diverifikasi.

## 3. Buat tabel dan fungsi melalui migration

**Tahap ini belum dikerjakan. Belum ada folder `supabase/migrations` atau SQL aplikasi siap diterapkan.**

Setelah mapping dan keputusan bisnis cukup, agent akan menyiapkan:

1. File migration SQL berurutan untuk schema, tabel, relasi, indeks dan constraint.
2. Grants dan RLS agar akses dibatasi menurut pengguna, permission dan depot.
3. Supabase Auth, profil pengguna, dan fungsi transaksi untuk workflow/upload/batch.
4. Schema `staging` untuk menerima data awal sebelum validasi dan transformasi.
5. Test pada DEV, termasuk pembatasan akses, proses serentak, duplikasi dan retry.

Nama seperti `claims`, `customers`, `campaigns`, `depots` dan `profiles` adalah **rancangan RC dalam instruksi**, bukan tabel yang sudah ada. Struktur final RC menunggu header/formula terkait. `campaign_upload_batches`, `campaign_upload_rows` dan RPC Document Center ditunda.

Jalur kerja yang disarankan untuk sesi ini: agent menyimpan SQL ke migration lokal, lalu menerapkan versi yang sama melalui MCP pada **DEV yang sudah diverifikasi**. Anda memeriksa hasil pada Table Editor. Sesudah mulai memakai migration, perubahan struktur tetap dicatat melalui migration; hindari perubahan schema remote yang tidak tercatat melalui SQL Editor. [Dokumentasi migration](https://supabase.com/docs/guides/deployment/database-migrations)

Jika memilih Supabase CLI, agent perlu menyiapkan CLI, konfigurasi project dan migration terlebih dahulu. Tidak ada perintah “push semua file sekarang” yang bisa mengubah backend Apps Script menjadi database secara otomatis.

## 4. Pindahkan baris data Spreadsheet ke Supabase

Migration membuat struktur; tahap berikutnya mengisi baris data. Urutannya:

1. Ambil snapshot/ekspor CSV sheet RC dengan timestamp dan cakupan yang jelas. Gunakan data sintetis/anonim pada DEV; tidak menjalankan atau menonaktifkan job Document Center untuk langkah ini.
2. Pertahankan No Document, kode depot/customer/campaign, batch, KTP, NPWP dan rekening sebagai **teks** agar leading zero tetap utuh. Verifikasi hasil ekspor; jangan hanya mengandalkan tampilan sel.
3. Masukkan CSV ke tabel `staging` yang kolomnya sudah disiapkan sebagai teks.
4. Jalankan validasi dan transformasi yang direkam dalam skrip. Baris invalid masuk laporan/tabel reject; tidak dibuang diam-diam.
5. Isi tabel final berdasarkan relasi yang sudah dipetakan. Akun pengguna disiapkan melalui Supabase Auth; PIN lama tidak disalin menjadi password permanen.
6. Cocokkan jumlah row, status, key unik, total nilai dan sampel dokumen dari sumber sampai tabel final. Laporkan selisih sebelum melanjutkan.

Supabase menyediakan import CSV melalui Table Editor dan metode bulk melalui koneksi database. Metode dipilih setelah ukuran ekspor diketahui; untuk proyek ini tujuan awal tetap staging yang sudah disiapkan, bukan tabel final dengan tipe hasil tebakan. [Panduan import data Supabase](https://supabase.com/docs/guides/database/import-data)

**Tanda tahap ini berhasil:** jumlah row dan nilai sesuai laporan rekonsiliasi; row yang ditolak memiliki alasan yang dapat ditelusuri. Munculnya beberapa tabel saja belum membuktikan data sudah lengkap.

## 5. Hubungkan frontend dan login

**Tahap ini juga belum diimplementasikan.** Mengganti URL Apps Script dengan URL Supabase saja tidak cukup, karena bentuk API dan autentikasinya berbeda.

Agent akan:

- Memindahkan login RC ke Supabase Auth dan menyiapkan shell RC DEV.
- Mengganti `fetchApp()` RC dengan adapter `supabase-js` v2 serta RPC yang sudah diuji. Integrasi Document Center dikerjakan pada tahap terpisah.
- Menyiapkan konfigurasi frontend berupa project URL dan publishable/anon key; secret/service-role key tetap di server.
- Mengganti full-dataset login dengan profil/permission/depot, lalu query terarah dan pagination.
- Membuat perubahan posting/workflow claim yang sukses langsung terlihat pada query RC dari database yang sama. Pasokan claim baru dari Document Center belum termasuk tahap ini.
- Menyiapkan direktori frontend publik tersendiri dengan entry point `index.html` serta perintah menjalankan versi migrasi.

Di Supabase **Authentication → URL Configuration**, atur Site URL dan daftar redirect sesuai alamat frontend DEV/PROD yang akhirnya dipakai, termasuk path repository bila menggunakan GitHub Pages. Akun login Supabase dashboard/MCP berbeda dari akun pengguna aplikasi. [Panduan URL Auth](https://supabase.com/docs/guides/auth/redirect-urls)

**Tanda tahap ini berhasil:** pengguna RC dapat login, hanya membaca depot yang berhak, memproses claim yang tersedia, dan langsung melihat perubahan status/nilainya di Supabase DEV.

### Pratinjau tampilan frontend lama — opsional

Konfigurasi `.vscode/launch.json` saat ini hanya membuka `http://localhost:8080`; ia tidak memulai web server. Untuk melihat halaman RC lama, salin hanya HTML RC ke folder sementara lalu jalankan server:

```powershell
Set-Location -LiteralPath 'D:\DANIEL\RC Next Gen'
$rcPreviewDir = Join-Path $env:TEMP 'rc-only-html-preview'
New-Item -ItemType Directory -Path $rcPreviewDir -Force | Out-Null
Copy-Item -LiteralPath '.\index (4).html' -Destination (Join-Path $rcPreviewDir 'index.html')
python -m http.server 8080 --bind 127.0.0.1 --directory "$rcPreviewDir"
```

Buka `http://127.0.0.1:8080/`. Hentikan server dengan **Ctrl+C**. Library CDN membutuhkan internet.

**Pratinjau ini masih memakai endpoint Apps Script lama.** Gunakan untuk melihat tampilan; jangan memakai login/submit/aksi perubahan sebagai pengujian DEV karena endpoint tertanam dapat mengarah ke sistem aktif. Menu Document Center lama masih membuka aplikasi PROD terpisah dan dikecualikan dari pengujian. Ini belum versi Supabase.

Jangan melayani seluruh root repository sebagai direktori publik: backend lokal mengandung secret yang sudah terdeteksi pada audit. Perintah di atas menyalin hanya HTML. Versi migrasi nanti dijalankan dari direktori publik yang disiapkan pada tahap 5; saat ini belum ada `npm run dev` atau entry point Supabase siap pakai.

## 7. Uji, lalu jalankan di produksi

1. Selesaikan rehearsal data, test role/depot, upload ulang/serentak, status, batch dan file ekspor pada DEV.
2. Siapkan backup/restore dan rencana rollback, termasuk delta bila PROD sudah menerima transaksi baru.
3. Setelah hasil konkret ditinjau dan penerapan PROD disetujui sesuai instruksi, terapkan migration serta import/delta pada project PROD yang benar.
4. Sebelum cutover RC produksi, tetapkan alur masuk claim baru selama Document Center masih PROD serta rencana satu writer dan rekonsiliasi. Detail ketergantungan produksi ini diperlukan saat cutover, bukan sebagai penghalang pekerjaan RC DEV sekarang.
5. Publikasikan **frontend yang sudah dimigrasikan** melalui deployment GitHub Pages yang digunakan proyek. GitHub Pages membutuhkan entry file seperti `index.html` pada sumber publikasi; jangan memublikasikan backend, ekspor privat atau secret bersama frontend. [Panduan GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)
6. Verifikasi URL RC, login, permission dan transaksi contoh yang disetujui. Cutover/penonaktifan trigger Document Center tidak termasuk cakupan saat ini.

Mengunggah HTML lama ke GitHub Pages tidak memigrasikan backend. Memasang extension, membuat tabel, mengimpor data, dan menerbitkan frontend adalah tahap yang berbeda dan perlu diverifikasi masing-masing.
